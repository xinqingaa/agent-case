- 前置知识：无

- 预计时间：10 分钟
- 学完后：能说明它是研究助手而不是通用聊天框，以及前端停在哪一层
- 当前把握：已按源码核对 / 还没跑过

## 一句话定位

DeepResearch 是一个多智能体研究工作台：用户提出问题，系统自动选择快速直答或「检索—裁判—成文」的调研链路，并尽量带上可追溯来源。

## 背景与问题

| 问题 | 受影响用户 | 原有处理方式 | 本项目的解决方式 |
|---|---|---|---|
| 调研要自己搜、自己判断来源、自己写结构 | 要做市场/方案/知识问答的人 | 搜索引擎 + 手工整理 | 意图分流后，复杂问题走规划、双源检索、证据裁判和写报告 |
| 多轮提问容易丢上下文 | 同一人连续追问 | 靠用户自己复制上文 | 用 user / thread / tenant 做记忆键，执行前注入、执行后写入（配置允许时） |

课程页脚出现在若干 Python 文件里（小滴课堂），说明这是教学向实现，不是已上线的商业产品。仓库根没有 README。

## 目标用户与使用场景

| 角色 | 主要任务 | 使用入口 | 期望结果 |
|---|---|---|---|
| 提问的人 | 调研、对比、知识问答 | 网页聊天 `front/agent_front` | 流式进度 + 一段 Markdown 结论 |
| 同一能力的调用方 | 不要 UI，只要结果 | `POST /api/v1/research/run` 或 `/stream` | JSON 终稿或 SSE 事件 |
| 本地试验 | 在终端跑同一套图 | 仓库根 `main.py` | 终端日志和最终文本 |

## 核心能力

| 能力 | 用户价值 | 实现边界 | 当前状态 |
|---|---|---|---|
| 意图分流 | 简单问题不必走完整调研 | 规则关键词 + LLM，结果只有 `direct` / `multiagent` | 已按源码核对 |
| 快速直答 | 低成本回答 | 一个 Direct Responder，不检索 | 已按源码核对 |
| 双源调研 | 网上资料 + 本地库一起用 | 博查 Web Search + Milvus RAG，缺密钥或服务则空结果 | 已按源码核对，未跑过 |
| 证据裁判与补搜 | 结论尽量可追溯，缺口再搜 | `deep_dive` → `analyze` → 可能 `reflect` | 已按源码核对 |
| 会话记忆 | 跨轮更稳 | Postgres / Redis / Milvus，失败则降级或关闭 | 已按源码核对，未跑过 |

## 输入与输出

输入：问题文本，外加可选的 `user_id` / `thread_id` / `tenant_id`。  
输出：`final` 字符串（调研时是 Markdown 研报）；流式过程中还有阶段消息。  
网页侧自己做了很浅的 Markdown 转 HTML，不是完整渲染器。

## 产品边界

### 包含

- 聊天式提问和流式反馈
- 简单/复杂两条执行路径
- 把外部检索和本地库接到同一张图里

### 不包含或尚未实现

- 账号登录、权限、计费
- 管理后台、知识库上传 UI（入库脚本在 `app/mult_agents/rag/ingest.py`，不是产品页）
- 完整测试体系
- 已验证的一键启动环境（配置关键字段目前是空的）

## 项目现状与版本

`pyproject.toml` 中包名 `mult_agents`，版本 `0.1.0`。前端包名仍是脚手架默认 `agent_front`。  
`config.json` 里 `api_key` 为空；`.env.example` 也没有博查密钥项。按源码，缺通义密钥时加载配置会直接失败。

## 先记住的三件事

1. 前端是研究工作台外壳，Agent 全在 Python 图里。
2. 复杂问题默认「网上搜 + 本地搜」，两路都可以空转（没密钥、没 Milvus）。
3. 现在所有「能跑」的判断都还没在本机验证过。
