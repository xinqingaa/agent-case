# DeepResearch 质量、风险与设计取舍

## 使用说明

本篇区分已观察实现问题 `[V]`、潜在影响 `[I]` 和尚未测量的指标 `[U]`。风险不表示已经发生事故。

## 安全边界

### 立即处理

1. 轮换疑似泄露的 Bocha Key；从当前文件移除，并按组织流程清理 Git 历史。
2. 在不读取内容的前提下隔离 `memory.db`，确认数据负责人和保留策略后再决定清理；任何读取需 L5/用户明确授权。
3. 删除 Key 前缀日志，统一使用“是否配置”的布尔状态。
4. 在 API 前增加可信身份层，tenant/user 由服务端会话生成，不能来自任意请求字段。

### 隔离修复原则

将 `(tenant_id, user_id, thread_id)` 作为单一上下文键，贯穿 LangGraph checkpoint、短期记忆、长期记忆、清理接口和日志 trace。降级后端必须保持同样语义，不能以“继续运行”为由退化安全边界。

| 路径 | 成本来源 | 当前指标 | 瓶颈判断 | 证据 |
|---|---|---|---|---|
| Direct | 意图 LLM + 回答 LLM | 无 | 至少两次串行模型调用 `[I]` | E-FLOW-005 |
| 深度研究 | Plan、双路 Scout、Judge、Analyze、Writer、可选 Reflect | 无 | 模型调用和外部检索可能主导 `[I]` | E-FLOW-004、E-FLOW-005、E-FLOW-006、E-FLOW-007、E-FLOW-008 |
| Web | 最多 6 查询 × 每次 4 结果/轮 | 无 | Bocha 30 秒超时，无重试 | E-FLOW-006、E-FLOW-008 |
| Local | 每轮最多 6 次 Embedding + Milvus search | 无 | 网络/向量库和集合规模未知 | E-FLOW-006 |
| Memory | 多存储读取、可选向量检索和摘要 | 无 | 首请求初始化和多次 DB 连接 | E-DATA-002 |

旧文档中的 `<8s`、准确率、幻觉率、覆盖率和毫秒级改善均缺指标定义、数据集、环境、脚本和日期，不可引用。[U][E-OPEN-007]

## 正确性边界

- source ID 白名单阻止不存在的编号，但不验证来源语义支持结论。
- LLM JSON 失败时 fallback 让流程继续，可能把“可用性”换成“静默低质量”。
- Deep Dive 对未纳入池的原始证据会再次补入，可能削弱 LLM 筛选意图。
- 当证据仍不足但达到迭代上限时强制写作，报告应显式披露未知，而当前只依赖 Prompt。
- SSE fallback 整图重跑可能产生重复费用和不一致输出。

## 技术债

- `nodes.py` 和 `MemoryManager` 职责集中，单元测试替换边界弱。
- `main.py` 同时承担 CLI、构建器和遗留节点。
- `rag/ingest.py` 有旧包路径和开发者绝对路径。[V][E-RISK-004]
- requirements 与 pyproject 范围不一致，版本策略不清。
- `tools.py` 保留大量未绑定 stub/tool，增加“项目已实现这些能力”的误解。
- 前端仅手写有限 Markdown 解析，没有任务取消、历史报告和重试控制。

## 关键设计取舍

| 当前设计 | 收益 | 代价 | 替代方案 | 何时替换 | 证据 |
|---|---|---|---|---|---|
| 固定 LangGraph 多角色 pipeline | 流程可见、可控、易插阶段 | 节点多、延迟和状态契约复杂 | 单 Agent structured workflow | 任务简单或成本优先 | `[V]` E-FLOW-004 |
| 规则 + LLM 意图 | 规则提供默认，LLM 处理语义 | Direct 也增加一次模型调用 | 纯分类器/规则置信度门 | 流量和成本上升 | `[V]` E-FLOW-005 |
| Python 直接检索，Agent tools 为空 | 外部调用确定、来源易约束 | 不是自主工具 Agent，扩展需改图/节点 | 工具路由器或受控 ReAct | 工具数量/组合显著增加 | `[V]` E-ARCH-009 |
| 多后端自动降级 | 演示环境更容易继续 | 能力和隔离语义悄然变化 | 启动时 fail-fast + 显式模式 | 生产和合规环境 | `[V]` E-DATA-002、E-DATA-003 |
| 引用正则白名单 | 实现简单，能移除编造 ID | 不验证 claim-source entailment | claim verifier + 引用覆盖检查 | 质量指标进入验收 | `[V]` E-FLOW-007 |
| 后台线程桥接 SSE | 复用同步图 API | 取消/背压/线程治理复杂 | 原生 async graph stream/任务队列 | 高并发或长任务 | `[V/I]` E-FLOW-003 |

## 改进路线

| 顺序 | 改进 | 验证方法 |
|---|---|---|
| 1 | 密钥轮换、移除数据库文件、日志脱敏 | secret scan、Git 历史检查、仓库规则 |

| 7 | 增加超时、取消、成本和 trace | 断连测试、节点级指标和预算上限 |
