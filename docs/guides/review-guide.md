# 评审指南

本指南给 Agent 和抽查人用。不要把它变成读者必修。

## 第一轮：范围与权限

确认调查没有超过能力矩阵，敏感目录和禁止操作得到遵守，源码保持只读。用户若只给了白话许可，核对 `project.yaml` 是否被正确翻译，而不是回头考用户背字段名。

## 第二轮：证据与矛盾

抽查产品、架构、核心链路、业务思路、风险和指标结论。后台核对证据 ID 和状态标记；学习文档核的是路径、模块和命令是否跟得上。发现文档与实现冲突时记录双方，不静默修正。

## 第三轮：跨文档一致性

比较产品步骤、架构图、核心链路、业务判断、数据状态、测试覆盖、练习和表达。重点检查同一入口、端口、组件或状态是否出现互相矛盾的描述。

## 第四轮：学习体验

按默认读者画像走一遍学习导航：能否讲清协作边界、一条链路的思路、前端参与到哪、出问题先看哪一侧。若只能复述目录而不能定位，则尚未通过。不要用「缺少编程背景的人能不能看懂实现细节」当验收标准。

## 最终检查

先运行机械校验，再填写人工结论和豁免。机械通过不能直接等同 G6 通过。
