# 文档编写指南

## 从问题开始

先回答读者需要理解的用户行为、系统结果和业务判断，再选择支持这些问题的源码。源码是 Agent 的核实材料，不是读者的课文。目录结构用于导航，不作为文章主线。

## 默认读者

按文档契约中的读者画像写：项目陌生，技术不是小白。不写纯前端实现教程。后端和 AI 只解释本项目真正用到的部分。深度按需，读者点名再展开。

## 写作顺序

1. 产品定位与用户旅程。
2. 环境候选、技术栈、架构和模块地图。
3. 数据模型和代表性核心链路。
4. 业务能力与思路、集成、测试、风险和取舍。
5. 练习与项目表达。
6. 最后回填学习导航。

## 控制篇幅

同一背景通过链接复用，不复制大段源码。代码片段只保留定位所需的最小范围。简单项目可以只有一篇核心链路；不适用主题用简短说明替代空模板。

学习文档用路径、模块或命令定位事实。证据 ID 和结论标记写在 `EVIDENCE.md`，不要堆在读者表格里。

## 面向读者

解释本项目的术语、状态变化、协作边界和调试入口。练习先做定位和解释，再按需做调试；不要默认要求改代码。每个练习都要有可观察的完成判定。
