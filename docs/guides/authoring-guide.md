# 文档编写指南

## 从问题开始

先回答读者需要理解的用户行为和系统结果，再选择支持这些问题的源码。目录结构用于导航，不作为文章主线。

## 写作顺序

1. 产品定位与用户旅程。
2. 环境候选、技术栈、架构和代码地图。
3. 数据模型和代表性核心链路。
4. 关键代码、集成、测试、风险和取舍。
5. 练习与项目表达。
6. 最后回填学习导航。

## 控制篇幅

同一背景通过链接复用，不复制大段源码。代码片段只保留理解所需的最小范围。简单项目可以只有一篇核心链路；不适用主题用简短说明替代空模板。

## 面向学习者

解释项目术语、框架生命周期、状态变化和修改影响。先给观察练习，再给解释、局部修改和跨模块扩展练习。每个练习都要有可观察的完成判定。
