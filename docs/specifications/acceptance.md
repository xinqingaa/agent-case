# 验收规范

版本：0.2.0
状态：试行

验收分为机械检查、事实检查和学习检查。脚本只能完成机械预检，不能代替人工判断。

## 机械检查

- 必需文件存在，至少有一篇核心链路。
- 没有模板占位符和未处理的 TODO/TBD。
- `project.yaml` 符合 Schema。
- 阶段状态、交付状态和授权字段合法。
- 文档引用的证据 ID 存在。
- `[R]` 证据具有运行记录。
- Markdown 本地链接和 Mermaid 围栏完整。
- 不包含活跃旧路径、真实密钥、个人绝对路径或敏感数据。

## 事实检查

- 产品步骤能映射到实现链路。
- 架构节点能定位到模块、进程或外部系统。
- 路径、符号、配置键和命令仍然有效。
- 推断、未知和用户确认没有被改写成实现事实。
- 失败、超时、重试和降级不是泛化描述。
- 指标包含定义、环境、方法、数据和日期。

## 学习检查

- 初学者知道先读什么、暂时跳过什么。
- 术语第一次出现时可以找到解释。
- 每篇有明确学习结果和下一步。
- 练习有范围、不变量、完成标准和验证方法。
- 面试材料区分项目事实、个人贡献和未来改进。

## 阻断项

以下任一情况存在时不得通过：无证据核心结论、伪造运行成功、没有端到端核心链路、只有目录罗列、没有失败路径、图无法映射到实现、无来源指标、练习不可判定、泄露敏感信息或存在未授权操作。

## 结论

- `未验收`：仍有阻断项或尚未进入 G6。
- `有条件通过`：仅允许用户明确接受的窄范围豁免，并记录后果。
- `通过`：目标交付状态的所有阻断项已通过。
