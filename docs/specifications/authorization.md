# 授权模型

版本：0.2.0
状态：试行

## 原则

授权由“便于沟通的等级”和“可执行的能力矩阵”共同组成。等级不能代替能力字段；任何缺失、未知或为 `false` 的能力都视为禁止。

## 参考等级

| 等级 | 典型范围 |
|---|---|
| L0 | 只建设规范、模板、计划和空工作区，不读取源码 |
| L1 | 查看目录、README、清单、配置示例和已有说明 |
| L2 | 阅读用户指定的入口、模块和核心链路文件 |
| L3 | 在项目内全局搜索并选择性阅读源码、测试和获准的 Git 历史 |
| L4 | 执行明确授权的本地安装、构建、启动、测试或浏览器验证 |
| L5 | 在明确边界内读取本地数据、队列或外部服务 |

等级表达调查深度，不自动打开同等级描述中的所有操作。例如 L4 不自动允许联网或读取数据库。

## 能力矩阵

| 字段 | 控制的行为 |
|---|---|
| `source_read` | 读取获准源码内容 |
| `git_history_read` | 查看 Git 历史和差异 |
| `command_execution` | 执行项目相关本地命令 |
| `dependency_install` | 安装或更新依赖 |
| `service_start` | 启动本地服务或进程 |
| `test_execution` | 执行测试、构建、类型检查 |
| `browser_access` | 使用浏览器访问本地项目 |
| `network_access` | 发起任何网络请求 |
| `local_data_read` | 读取本地数据库、队列或运行数据 |
| `external_service_read` | 只读访问外部服务 |
| `source_write` | 修改被分析项目源码 |

## 授权记录

每次授权或升级必须记录日期、授权者、范围、限制和变化原因。涉及网络、数据、外部系统或源码写入时，必须单独确认具体目标；“开始拆解”不能解释为 blanket permission。

## 永久默认限制

- 不读取真实密钥、认证令牌或个人数据。
- 不调用生产写接口。
- 不执行迁移、清理、上传或破坏性命令。
- 不修改 `sources/`，除非用户另行发起源码修改任务。
- 发现潜在密钥或数据文件时只记录存在性和风险，不展开内容。
