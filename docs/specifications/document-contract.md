# 详细版文档契约

版本：0.2.0
状态：试行

详细版不是一组独立文章，而是一条从产品到实现、从理解到验证、从学习到表达的证据链。

```mermaid
flowchart LR
    Product[01-02 产品] --> System[03-06 环境与架构]
    System --> Data[07 数据与状态]
    Data --> Flow[08 核心链路]
    Flow --> Code[09 关键代码]
    Code --> Quality[10-12 集成、测试、风险]
    Quality --> Learn[13-14 练习与表达]
    Learn --> Guide[00 学习导航最后回填]
```

## 文档集合

|---|---|---|
| `00-learning-guide.md` | 应按什么顺序学，如何判断学会？ | 最后编写，必需 |

| `03-environment-and-runbook.md` | 如何准备、运行和判断成功？ | 必需，可保持未验证 |
| `04-stack-and-dependencies.md` | 哪些技术真正影响架构和运行？ | 必需 |
| `05-architecture.md` | 系统边界、模块和运行时如何协作？ | 必需 |

项目根还必须包含 `project.yaml`、`EVIDENCE.md`、`GLOSSARY.md`、`ACCEPTANCE.md` 和非事实源的 `working/`。

## 单篇共同要求

每篇开头说明前置知识、阅读目标、预计时间和当前验证状态；正文中的非平凡结论引用证据；结尾说明完成判定、未知项和下一篇。主题不适用时保留简短说明和证据，不用空模板充数。

## 核心链路要求

每篇 `08` 必须包含触发与结果、顺序图、关键节点表、数据或状态变化、失败/重试/降级、测试覆盖、代码阅读顺序和验证方法。

## 代码精读要求

按链路关键性、业务决策密度、状态变化、外部边界或修改风险选择符号。解释其职责、调用者、被调用者、输入输出、副作用、不变量、边界条件、修改影响、常见误解和设计取舍；避免逐文件复述。

## 横向一致性

产品链路变化必须同步检查架构、核心链路、练习和表达；运行变化同步检查运行手册、测试、证据和验收；数据变化同步检查核心链路、精读和风险；外部接口变化同步检查架构、运行手册、测试和风险。

## 简洁版

只有详细版通过相应 G6 后才能派生简洁版。简洁版不得新增事实、指标、设计理由或个人贡献。
